Document Access Trail

The only reading door onto log_document_access, and the only access-control surface in Document Service. Pure oversight — zero write levers. Exactly two roles may read it: ROLE_SUPER_ADMIN and ROLE_HR_MANAGER.

Three facts this dataset proves

1 · An owner opening their own file is still recorded — zero exceptions (DOC-30.3). 2 · flagged_unreasonable is the main brake on centralising Employee Files (DOC-69) and has no threshold-setting address (PROB-SERVICE-434). 3 · An empty document_id is legitimate after the document was swept — fact-versus-evidence, not data loss.

Honest limits — do not smooth these over

source_ip is stored on every row but is not shown as a column and not the accessor’s address: SNAT strips the client address before the gateway, so the stored value is the node/gateway address — one office, one address, zero power to tell people apart (PROB-INFRA-047). Every row in this dataset carries 10.0.3.134. Labelling it “accessor address” is forbidden. Reading the trail leaves no trail — the watchers are not watched (PROB-SECURITY-091), and a read request refused with 403 is not recorded at all (PROB-SECURITY-086). The oversight here is mutual, not external: if both readers agree, nobody inside the system sees it — the real boundary of the zero-new-role decision (DOC-33).

No free-text search — on purpose

Every filter is a uuid, an enum, a boolean or a date. Which addresses write here: only A2, committed before the first byte is released. A3 and A4 write nothing — a list or a description is not an opening. And ROLE_HEALTH_DATA_OFFICER, though allowed to open SENSITIF content, is deliberately absent from this screen: watched, not watching.
