Employee Files

Documents owned by an employee — owner_type=KARYAWAN plus an owner_id that must be picked first. This is the only file screen that carries the employee-service dependency, and the only one that demonstrates the SENSITIF branch.

Why the pick comes first, and why there is no flat list

A flat list of every employee file would be a bulk-copy tool (DOC-69). Forcing the pick makes any widening of scope countable — it is what flagged_unreasonable in the access trail measures. This step belongs to employee-service, not to Document: it only supplies the employee_id that fills owner_id on every A3 call. The list is a paged search (page + size) already scoped to what you may see — the whole payroll never lands on one screen.

Two-layer scope filter, fail-closed

The chain is two long — employee → company. If either link falls, the grid comes back empty; that is correct behaviour, not an error. The per-row read-right filter runs on the server, so a row you may not open never reaches the screen.

Origin column deliberately dropped

Unlike Company Files this grid does not show origin — the contract still accepts it as a filter. Employee identity is shown as NIK; employee_id is never printed on screen.
