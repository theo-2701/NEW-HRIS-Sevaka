Document Templates

The letter-draft library. ROLE_HR_MANAGER writes and maintains drafts; ROLE_SUPER_ADMIN is the second pair of hands that approves a draft before any letter can be issued from it. ROLE_HR_STAFF has zero access here — it only picks templates, through A15.

Draft lifecycle — template_version_state

MENUNGGU_PERSETUJUAN → DISETUJUI or DITOLAK. Approval fields stay NULL until a decision lands. The active_version_id pointer moves only when the approved draft is the newest one; older approved drafts stay approved forever, so an old letter can still be re-born from them. DITOLAK is terminal — the only way forward is writing a new version from scratch.

Honest scope limits

Deactivated templates cannot be found through this grid (A8a lists is_active=true only) — they are readable through A8e if you hold the id. There is no “reactivate” address; the absence is deliberate. A rejection reason (reject_reason) is written to the event log and no address returns it (PROB-SERVICE-433). The permission matrix in STD still has no Document column (PROB-SERVICE-342).

Template detail

GET /document-templates/{template-id} — every draft is served with its full body, because the second pair of hands judges by comparing.

New template

POST /document-templates — ROLE_HR_MANAGER only. Version 1 is born MENUNGGU_PERSETUJUAN and active_version_id stays NULL.

Select category

PICKER → A6a — the cross-page category list, not A16: this form is inhabited by ROLE_HR_MANAGER only.

Attached to the template, never chosen by the issuer.

Max 100,000 characters and max 200 %%marker%% placeholders. Template-engine expressions are rejected (422).

Five fields deliberately not accepted

category_origin · confidentiality_class · is_active · id · has_pending_change — sending any of them returns a named-field 422, never a silent ignore. Also server-owned: company_code, active_version_id, version_no (always 1).

New draft version

POST /document-templates/{template-id}/versions — the whole body, not a patch.

The active-version pointer is not touched

Issuance running right now keeps using the old approved draft, undisturbed, until this one is approved. Two simultaneous edits collide with 409.

Decide on draft

POST .../versions/{version-no}/approve — ROLE_SUPER_ADMIN only. “Reviewer ≠ author” is enforced by the server (422).

Stored in the event log only — no address ever returns it (PROB-SERVICE-433).

Deactivate template

POST .../deactivate — no second pair of hands, no request body, idempotent. There is no way back: no “reactivate” address exists.
