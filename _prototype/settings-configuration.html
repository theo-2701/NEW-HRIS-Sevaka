Settings

Eight menus, one read door and one write door. A single read returns every setting the caller is allowed to see — the per-menu split happens on this screen, not on the server. Saving sends only the edited rows as one list and applies them in one transaction: if a single row is refused, nothing changes at all.

Every refused row is reported at once and the transaction is rolled back whole — zero settings changed. The top-level status is the harshest code in the batch: locked beats not-offered beats validation. The refusal is written down as a security event.
