# MOM 28 Oktober 2026 — Review Core HRIS bersama HR (ringkasan)

Sumber: `MOM_New_HRIS_28_Oktober_2026.pdf` (dilaporkan Yota Pratama & Theodorus Fredrik Kiatra, 29 Okt 2026).
Peserta: Project Owner, GM HRD, Deputy Manager HRD, TL HR KP, System Analyst, Lead Dev, Dev, QA.
Agenda: demo alur New Joiner sampai Transition; identifikasi gap terhadap kebutuhan PT DIKA.

## Produk & roadmap
- HRIS dibuat untuk dijual (acuan: Mekari/Talenta); PT DIKA klien pertama, gap = backlog.
- Urutan: **Core HRIS → ATS → Payroll**. Segmen: Corporate (<600), Project (~12.000), Sales (~6.000).
- Harapan end-to-end: lamar → HRIS → payroll.

## New Joiner & requisition
- Urutan alur disepakati: **requisition → approval → pencarian kandidat → interview & pemilihan oleh user →
  validasi HR → kontrak digital → provisioning**. Requestor wajib; tak ada karyawan tanpa penanggung jawab.
- Data kandidat real time ke HR + notifikasi.
- Struktur organisasi (grup, level, jabatan, jobdesk, gaji) ditetapkan di awal; requisition menampilkan
  departemen, jabatan, level, jobdesk, kualifikasi, gaji dari Position Setting. "Active From" = tenggat
  pencarian kandidat.
- Approval requisition linear ke atas, maker ≠ checker. Penggantian → sampai direktur masing-masing;
  penambahan → sampai Direktur Utama. **Aturan approval configurable di Global Setting.**
- Kandidat dipilih requestor (hasil + alasan interview) → bucket HRD + notifikasi; kandidat lain tereliminasi.
  Selama ATS belum ada: bypass sementara.

## Data karyawan baru
- HR = validator/checker; data diisi kandidat/digenerate; edit HR lewat lock/unlock.
- Grade dari golongan posisi; posisi & role dari mapping. Field "Role" tercampur akses sistem vs jabatan.
- Bank & rekening diisi kandidat, HR validasi. **Company email = wewenang IT Support**, tidak wajib bagi HR.

## Kontrak & tanda tangan
- Kandidat centang pernyataan, OTP email/HP, selfie saat tanda tangan (flow PT DIKA, sesuai Komdigi).
- Produk: tanda tangan bersertifikat (PrivyID/e-meterai) ditawarkan dulu, flow PT DIKA alternatif.

## Provisioning & akses
- Aktivasi email kantor + akses sistem disatukan satu langkah.
- **Pisahkan menu System Admin dan HR Admin**; verifikasi email = tugas System Admin/IT; field sesuai role;
  istilah teknis → bahasa HR.
- Email & akses nonaktif otomatis saat offboarding; karyawan meninggal diproses admin HR.

## Transition
- Task Out (kewajiban posisi lama, handover, aset) dan Task In (fasilitas, akses, administrasi). Workflow di
  Settings (Materialization). Detail ditunda.

## PDP
- Consent sekali di awal (tahap ATS), diisi kandidat sendiri.
- Masking dinilai merepotkan; masking gaji tetap. **Watermark toggle di Global Setting.**
- Audit log siapa melihat data kapan. HRD bertanggung jawab atas data (consent + NDA).

## Catatan terbuka
- Strategi jual per modul vs end-to-end belum diputuskan; selfie di awal pendaftaran belum diputuskan;
  kebutuhan Project & Sales belum dipetakan; PIC backlog belum ditetapkan.
- Rapat berikut: Onboarding, Offboarding, Transition, kebutuhan PT DIKA — **dipisah per peran (Admin, HR,
  User)** dengan istilah non-teknis.
